# 藥安・本機高齡用藥評估原型

## 🌐 給其他人一起使用的公開網址與方式

- **雲端高齡病人用藥安全評估 UI（GitHub Pages 公開網址）：**
  🔗 https://samlord7app-ops.github.io/elder-medication-review/
- **打開此網站點擊右上角「下載 Windows 本機套件」取得免安裝壓縮包：**
  🔗 https://github.com/samlord7app-ops/elder-medication-review/releases/latest
- 下載安裝 **`ElderMedicationReview-Windows-x64.zip`** 後即可使用：
  1. 解壓縮後，進入資料夾找到 **`ElderMedicationReview.exe`** 點兩下執行。
  2. 若跳出藍色的「**Windows 已保護您的電腦 (Microsoft Defender SmartScreen)**」：請點選左上角的「**其他資訊 (More info)**」→ 再按右下角的「**仍要執行 (Run anyway)**」。
  3. **首次啟動需要約 1～2 分鐘建立 29 萬筆藥品資料庫索引：**
     - 第一次點開 `ElderMedicationReview.exe` 時，黑色視窗會顯示：`Building public offline catalog; this may take a few minutes.`
     - 在這 1 分鐘建立索引的期間，服務還沒正式監聽 `127.0.0.1:18743`。如果這時候直接去點網頁上的「開啟本機端工作台」，瀏覽器就會顯示 `127.0.0.1 拒絕連線`。
     - 等它建立完索引（約 1 分鐘），黑色視窗會顯示 `Local-only review workstation: http://127.0.0.1:18743`，並且會自動幫使用者彈出瀏覽器進入工作台（第二次之後啟動則是 1 秒鐘瞬間開啟）。
     - 使用期間**請勿關閉該黑色服務視窗**（縮小即可）。
  4. **之後每次使用前，均先執行 `ElderMedicationReview.exe`。**

---

**藥名＋品項含量：** 支援 Lipitor 10 mg、立普妥 10毫克等目錄比對；雲端候選也會檢查含量並於套用時保留含量與劑型。不符或不確定時不改配其他規格，單顆含量不會當成每日總劑量。

**選用雲端藥名核對：** 人工校對區可展開雲端核對，每次人工確認 1–5 個藥名後，才傳至 NLM RxNav 官方服務取得英文近似藥名及成分候選。圖片、Excel、原文、年齡、診斷、檢驗與臨床評估不傳送。中文／台灣代碼仍使用本機 TFDA／健保目錄；候選不會自動套用，複方不提供一鍵成分替換。外部服務會收到確認的藥名及連線 IP，無法撤回已送出的查詢；本機程式不保存查詢日誌。

**整合 UI：** http://127.0.0.1:18743/ 現已整合圖片／Excel 匯入、核對、條款分析表、儲存評估、日期區間統計與 CSV 匯出。紀錄留在本機瀏覽器，支援備份及匯入舊版備份。雲端入口的「開啟完整評估與統計 UI」會開啟同一套介面。舊版 index.html 仍只作舊資料遷移及示範，新結果請在整合工作台保存。

**雲端入口／可下載本機服務：** 部署設定與 Windows 套件流程已加入，見 [SHARING.md](SHARING.md)。雲端只發布 `cloud-ui/`；處方輸入、解析與評估留在本機工作台，沒有病人資料上雲 API。

**條件式篩檢已擴充：** 本機工作台新增藥品劑量／療程／途徑／適應症欄位，並可執行 90 個條件分支；尚非三套準則完整自動化或經機構臨床驗證。請先閱讀 [CLINICAL_RULES.md](CLINICAL_RULES.md) 的實際範圍與限制。舊的獨立 index.html 仍是小型示範，臨床引擎只接在本機 API 工作台。

**公開資料已匯入：** 本機 API 現可使用 TFDA／健保署完整下載快照作目錄辨識；歷史紀錄、授權與文獻匯入狀態見 [REFERENCES.md](REFERENCES.md)。GitHub 新下載者先執行 `python import_public_data.py --from-bundle` 建立本機索引。下文舊工作站的小型字典與示範規則限制仍保留；官方目錄不代表完整臨床判讀。

新增「圖片／Excel 匯入與核對工作台」：在 PowerShell 執行 `./start-local.ps1`，再開啟 http://127.0.0.1:18743/ 。支援圖片貼上、Windows 本機 OCR、.xlsx 欄位選擇、人工校正、去識別 JSON 預覽與本機 API 回傳。操作方式、隱私邊界及限制見 [API.md](API.md)。既有 `index.html` 工作站仍可獨立使用。

直接以 Edge 或 Chrome 開啟 `index.html`，無須安裝套件、帳號或網路。使用「載入示範 → 開始本機評估 → 儲存本次評估」體驗流程。請固定使用同一瀏覽器與檔案位置，並定期下載備份；file URL 的儲存行為由瀏覽器決定，正式部署應改用固定的院內來源。

## 已實作

- 每行輸入藥品名稱或代碼，精確匹配本機別名，支援多成分及多筆匹配警示。
- 風險提示、原因、規則來源、未辨識狀態；修改輸入後需重新評估。
- 匿名案件、評估日期、年齡、場域、覆核狀態、結果及版本快照。
- 日期區間及藥品類別統計、匿名明細 CSV、統計 CSV。
- 藥品與規則 JSON 編輯／匯出、本機案件備份及還原。

## 隱私與限制

全部計算使用瀏覽器 JavaScript；案件與規則存於 localStorage，沒有任何後端、遙測、外部資源或雲端比對。CSP 設定 connect-src 'none'。參考來源連結只有使用者點擊時才開啟外部網頁，連結不帶病例資料。

不要輸入姓名、身分證號、病歷號等資訊。基本輸入攔截無法可靠偵測所有個資。匿名用藥資料仍屬敏感資訊；本機儲存與下載備份尚未加密，裝置管理員、瀏覽器擴充、同步軟體或共用帳號可能存取資料。本資料夾位於 OneDrive，請將程式與備份移至經機構核准、未同步的本機位置後再處理任何真實資料。

此為 UI 與工作流程原型，沒有完整台灣藥品目錄；沒有填入未查證的健保碼或許可證字號。示範資料只含 Diazepam、Diphenhydramine（口服）、Zolpidem 及 Metformin；後者僅示範「已辨識但未命中」，不表示安全。未涵蓋完整 Beers、STOPP/START、台灣共識、劑量／療程、疾病、腎功能、交互作用與例外情境。不得據此自動停藥或作正式評鑑結論。

## 正式版建議

由藥師確認適用準則及授權，將 TFDA 藥品許可證與健保署品項檔離線匯入，建立商品／代碼→成分→臨床規則的版本化對照。保留待確認佇列及人工覆核。正式資料庫採機構內網或本機加密資料庫，加入角色權限、變更稽核、備份復原及保存政策；外網更新程序只能取得公開藥品資料，不得帶入個案內容。

統計以「評估次數」計算，同一人重評另計；每個藥品於同一風險類別計一次，多類別可以重複。指定類別時，分母限包含該類提示的評估，因此該類提示案件比例可能為 100%，不是全體病人的盛行率。

參考：AGS 2023 Beers Criteria https://pmc.ncbi.nlm.nih.gov/articles/PMC12478568/ ；健保署用藥品項 https://www.nhi.gov.tw/ch/lp-2466-1.html 。示範摘要不能取代原始規則。
